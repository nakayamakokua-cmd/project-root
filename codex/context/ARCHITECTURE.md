判定規則（実装：時系列優先・終話基準）

目的：同一通話内で複数のNG候補が出た場合、時系列ベースで「実際に終話を決めた理由」を最終NGとして確定する。
大分類に1~6の大分類を反映、各1〜6の内部にあるa~gなどの英数字に該当する理由を反映。どちらも英数字ではなく、日本語の理由を記載。 また、NG理由は相手の発言内容から時系列順でカンマ区切りで理由を記載する
ルール概要

候補抽出

#2以降（接触後）を走査し、NG辞書・ルールに一致する発話を候補タグとして抽出。

候補ごとに {timestamp, speaker, ng_major, ng_minor, text, confidence} を保持。

終話ウィンドウの定義

終話直前の 30〜90秒 を「終話ウィンドウ」とする（実装は60秒をデフォルト、短い通話は20%ルールで調整）。

加えて、最後の否定/断り発話から遡って1往復（OP↔CUS）分もウィンドウに含める（言下の断り・丁寧終話に対応）。

最終NGの確定（時系列優先）

終話ウィンドウ内に候補がある場合：→ 最も後ろに出現した候補を最終NGに採用。

終話ウィンドウ内に候補が無い場合：→ 通話全体から **「最後に出現した“確定度の高い”候補」**を採用。

確定度の序列（同時刻タイ）は下記「確定度スコア」で決定。

候補が1つもない場合：→ ng_major="不明", ng_minor="不明"（要レビュー）で出力し、ng_evidenceに終話前後の発話を格納。

例外：撤退系

顧客が**「受け取りではなく発行の話なら不要」などで撤退が明示**され、OPが会話を終了した場合：→ その直前の候補（例：発行/受取の誤認）を最終NGに採用。

確定度スコア（タイブレーク用）

終話ウィンドウ外で“最後の候補”が複数並ぶときに使用します。確定度 = 発話強度 + 話者重み + 明示度 + 一貫性ボーナス

発話強度（-1〜+2）

+2：終話を明示（「結構です」「お断りします」「必要ありません」「切替予定なしです」等の決定文）

+1：強い否定（「今後も予定ない」「検討しません」）

0：弱い否定/条件付き（「今は」「忙しいのでまた」）

-1：情報提供/背景説明のみ（「親会社運用です」「税理士任せ」※否定語なし）

話者重み（0 or +0.5）

+0.5：顧客の発話（決定権者なら +1.0 まで加点）

明示度（0〜+1）

+1：中分類が明確に特定可能（競合名、親会社方針、委託先名 等）

+0.5：カテゴリは特定できるが中分類が曖昧

一貫性ボーナス（0〜+0.5）

+0.5：同カテゴリの表現が連続して2回以上出現

実装では 0.5刻み程度で十分です。タイは“時刻が後”を優先。

擬似コード

candidates = extract_ng_candidates(segments)  # [{t, speaker, major, minor, text, conf}, ...]

end_t = segments[-1].end
window_start = max(0, end_t - max(60, total_duration * 0.2))
window = [c for c in candidates if c.t >= window_start or is_within_last_exchange(c, segments)]

def certainty(c):
    s = 0
    s += utterance_strength(c.text)       # -1..+2
    s += 0.5 if c.speaker == "CUS" else 0
    s += 1.0 if minor_is_explicit(c) else (0.5 if major_is_explicit(c) else 0)
    s += 0.5 if is_consistent_chain(c, candidates) else 0
    return s

if window:
    final = sorted(window, key=lambda c: c.t)[-1]  # 時系列最後
else:
    # 通話全体の最後に近い高確度
    tail = candidates[-5:]  # 終盤に寄せる（負荷軽減）
    final = sorted(tail, key=lambda c: (c.t, certainty(c)))[-1] if tail else None

if final:
    ng_major, ng_minor = final.major, final.minor
    ng_evidence = collect_window_evidence(final, segments)  # 前後1発話も含める
else:
    ng_major, ng_minor = "不明", "不明"
    ng_evidence = collect_ending_context(segments)

動作例

例1：前半「他でやってます（競合））」→ 中盤「今は検討しません（導入未検討）」→ 終話直前「営業お断り」→ 最終NG＝「営業一律お断り（3.c）」※終話ウィンドウ内の最後の断りを採用

定義（フェーズ境界）

#1 受付：最初のOP発話開始〜担当者（経理）の自己同定が確定するまで

例：「お電話口の方は経理のご担当者様になりますでしょうか？」→「はい、担当の◯◯です」の直前までが#1

#2 担当者接触後：経理担当と確定してから、#3に入るまで

例：「以前お電話したBillOneの…日程調整できれば…」の導入パート

#3 内容説明〜分岐：下記の分岐タグが付く発話区間の合算

#3-1 内容説明（E1〜E4の説明や「情報提供」主旨、日程打診を含むターンの本体）

#3-2 システム系（導入済/競合/会計非対応 等への切り返し）

#3-3 導入未検討系（「今は検討していない」等への切り返し）

#3-4 時期系（「忙しい/予定が見えない」等への切り返し）

フェーズ判定は、既存の**「トークスクリプトの分岐遷移」タグ付け**（#2→#3-x）ロジックを利用。タグの出現区間をそのまま時間集計に使います。

算出ルール

総時間：total_duration_sec = 最後の発話終了時刻（ms） / 1000

フェーズ時間：

各セグメント（segments[]: {start_ms, end_ms, speaker, text, phase_tag}）を走査

phase_tag ∈ {#1, #2, #3-1, #3-2, #3-3, #3-4} の秒数をすべて合算

phase_time_sec__p3_content_all = p3_1 + p3_2 + p3_3 + p3_4

被り発話がある場合：

フェーズは話者ターンの主タグに依存。OP/CUSが同時でも区間の二重計上はしない（セグメントは交互のターン分割を前提）

タグ付けできない区間（無音/雑談等）：

#2〜#3 の間に挿入される雑談や長い無音は、直前フェーズを継続としてカウント（例外処理：無音>10秒は除外してもOK）

出力フォーマット：整数秒（四捨五入）

話速（WPM）

✅ WPM（話速）しきい値（初期案＋解説）

定義：1分あたりの日本語単語数。日本語は“形態素数/モーラ近似”でばらつくため、ターン長（秒）と文字数から近似推定する。初期しきい値（推奨）

オペレーター（OP）：130–170 WPM（これより速いと圧が強く、遅いと冗長になりやすい）

顧客（CUS）：110–160 WPM（顧客のペースを尊重、OPより低めを自然と想定）
運用

ターン単位でWPMを算出 → 通話全体の中央値と**上位/下位10%**を出す。

アラート条件（例）：OPの中央値が170超、または上位10%が185超が連続3ターン以上。

なぜこの帯域？

コール現場の日本語対話では150±20が最も聴取・応答の両立が取りやすい。

実地で「早口→否定が増える」「遅口→被り/割り込み増」の傾向が出やすい。

しきい値は初期値。運用3週間分を見て、高成績者の分布に合わせて±10調整する想定。

マネジメントコメント

✅ マネジメントコメント（生成ルール：抜粋）

観点1：ゴール達成 — 各ターン末尾で日程打診が無ければ最優先で指摘＋推奨文例を提示。

観点2：意味要素の欠落 — 足りないE1〜E4を指摘し、該当通話の成功例（Chromaから近似）を引用。

観点3：否定トリガー対応 — sentiment_triggersのトピックと紐づけ、次の一言テンプレを提案。

観点4：速度・被り — WPM/被りが閾値超なら、話速調整ガイド（1拍置く/短文化/確認質問）を助言。



3. 解析ロジック（Gemini 2.5 Pro 活用）

固定プロファイル（System Prompt）：プロジェクト目的、NG分類定義、分岐規約、算出ルール、JSON出力形式

通話ごとプロンプト（User Prompt）：Gemini 2.5 Proの文字起こし出力（話者タグ・時刻付き）＋メタ情報

算出指標：言語特徴（肯否比率、反論回数、打診回数、キーワード網羅率）、音響特徴（WPM、ピッチ、音量安定、Overlap）、感情推移とトリガー抽出、NG分類推定

出力：スキーマ準拠JSON → スプシ＆ChromaDB保存

適合度評価時は、セマンティック類似度（Embedding）＋ルール判定のハイブリッドで計算。

NG分類の自動推定は、スクリプト適合度・感情変化トリガー・顧客否定表現の強度を組み合わせて精度向上。

反論処理回数・日程打診回数は、正規表現ベースのパターンマッチ＋類義語辞書を使用。

✅ 解析の二段構成（確定）

ステップA（APIコール1回）：構造化抽出（NG分類、分岐、適合度、各カウント、感情スコア粗度）。

ステップB（APIコール1回）：根拠抽出 & マネジメントコメント（該当発話の引用、改善アドバイス生成）。

合計 2回呼び出し。Aの結果をBへ条件付きで渡す（RAG/メタ限定）。
