# 音源分析 基本設計（拡張MVP版）— Codex コンテキスト要約
目的：通話ごとの定量/定性評価を自動化。NG要因の可視化→現場コーチング→改善サイクル高速化。
入出力：音声(mp3<=60min)->Gemini2.5Pro(文字起こし+話者分離)->解析->Googleスプレッドシート 1行追加。
初期MVP：ChromaDB/ダッシュボードは後回し。まずスプシ追記の正確性を担保。

## スプレッドシート列（シート「NG分析」）
既存ヘッダー15列を前提に、MVPは下記を最小実装で埋める：
- ファイル名（=音源ID） / NG理由・断り文句（抜粋 or 根拠抜粋） / 話者（OP候補名） / 処理日時 / ファイルID
- チェック内容（=アポ取得タグや判定メモ） / アポ取得タグ（例：NG回避 等） / NG分類（大>中 文字列） / 電話番号
- 会社名 / 法人番号 / HP / 大業種 / 中業種 / 従業員数 … はMVPは空でよい

## 重要ルール（抜粋）
- 電話番号：ファイル名「YYYY-MM-DD_0123456789_...」の**2番目トークン**を数字のみ抽出→先頭0の**ハイフン無し**で保存。10/11桁以外は「不明」フラグ（内部）。
- 分岐パターン：**最初の顧客反応**で固定。 {#3-1,#3-2,#3-3,#3-4, MEDAPANI(#2直→日程)}。
- 最終NG：終話ウィンドウ(60s or 全体20%)内で最後に出た候補を最終NG。無ければ終盤高確度。
  確定度=発話強度(-1..2)+話者重み(+0.5)+明示度(+1/0.5)+一貫性(+0.5)。タイは後時刻優先。
  根拠は「決定発話+前後1発話」を evidence に保存。スプシは抜粋200字まで。
- トーク適合度(#3-1)：E1~E4(各20)+末尾の日程打診(+20)=100。strict=0.7。
- 日程打診回数：各 #2/#3 ターン末尾のみ 1回カウント。同一ターンの微調整は束ねて1回。
- リードタイム：通話日→代表日（具体日/◯日週/来週/曜日などの正規化）。祝日考慮は初期無し。
- 通話フェーズ時間：#1,#2,#3-1..#3-4 の**出現回合算**（整数秒、±5%ずれで内部フラグ）。

## 解析I/O
入力：transcriber出力(JSON): transcript_text, segments[{t,speaker,text}], file_meta{date,phone,filename,processed_at}
辞書：config/ng_master.json, config/script_master.json
出力：スプシ1行相当のJSON（既存15列を埋める）。長文は冒頭抜粋を利用。

## 実装方針（MVP）
- analyzer.py はローカル計算のみ（追加API不要）。辞書とルールで推定・集計。
- sheets_writer.py は append 専用。httplib2 timeout=180s、tenacity retry(最大5回)、updatedRange を必ず出力。
  --dedupe-key FILE_ID で既存「ファイルID」列に同一IDがあればスキップ（MVPでは上書きしない）。
